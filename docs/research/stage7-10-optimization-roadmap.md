## 二、两个参考项目怎么用

### OpenAI-Data-Analytics：借用方法，补齐可执行契约

重点借鉴 `create-data-context`、`analyze-data-quality`、`product-business-analysis`、`validate-data`、`jupyter-notebook`、`gather-business-context`、`metric-diagnostics`。

将其“定义问题—确认口径—检查数据—计算—验证结论”的方法落实为机器可校验的输入、工具调用和检查产物。检查项包括粒度、关联基数、分母、缺失值、样本范围、时间窗口、方法假设和证据来源。

已核对的仓库版本主要提供工作流说明；`mcp/server.cjs` 与数据上下文校验脚本均为空。不能通过安装这些 Markdown 就宣称已经获得计算或验证能力。当前目标是把方法适配到 GeneralDataAgent 已有执行器，而不是照搬其特定产品界面、连接器或发布步骤。

### AutoKaggle：借用有测试的分阶段改进循环

借鉴 Reader / Planner / Developer / Reviewer / Summarizer 的职责分离、阶段状态、错误调试、测试后修复和工具目录。参考项目中存在实际代码执行、数据处理函数和阶段测试，并非只有提示词。

这些职责可以先作为少量逻辑步骤实现，按复杂度才启用多角色；不要求每道简单查询都经历五个 LLM 会话。Reviewer 的建议不能替代确定性断言，生成代码跑完也不等于业务答案正确。

本项目已有 Stage 3 的快照、实验契约、OCI 沙箱、跟踪和验证能力，应复用。其当前回归固定模板是均值基线，并不是任意特征的 sklearn 建模；需要新增版本化计算模板。AutoKaggle 的直接生成代码子进程执行方式、默认 80/20 切分、阶段重试次数等不能未经适配就替代现有治理与题目方法要求。

## 三、四期实施路线

| 期次 | 核心交付 | 优先覆盖的错误 | 拟定开发队列目标，不是预测成绩 |
|---|---|---|---|
| 第七期：语义与 SQL 正确性 | 问题契约、语义上下文、SQL 检查、工具参数校验 | BIRD 语义错误与跨轨道无效动作 | BIRD 从 28/60 向至少 36/60 推进；保护另外两轨已有正确题 |
| 第八期：统计与数据科学计算 | 派生特征、统计检验、多变量模型与真实留出集评估 | InfiAgent 的统计误用、特征计算和建模缺口 | InfiAgent 从 32/60 向至少 42/60 推进；覆盖五个“不支持”案例中可确证的能力缺口 |
| 第九期：文档规则与复杂业务分析 | 可追溯规则模型、确定性费用计算、子任务图与证据汇总 | DABstep 的多资料、多步骤和费用规则问题 | DABstep 从 1/10 向至少 5/10 推进；另建独立业务题集，避免只优化十题 |
| 第十期：经验复用与泛化验收 | 版本化 Skill 注册、反思案例、预算路由、完整产品接入 | 重复失败、长任务失控、开发集过拟合 | 在新题/新资产上确认收益，完成至少三次配对重复与资源评估 |

目标以当前公开开发队列为迭代里程碑。未见数据、重复稳定性、费用和独立审阅是另外的推广门槛，不能用达成表内分数代替。

### 第七期：先把“问题理解正确、SQL 执行正确、结果回答正确”连起来

1. **问题与答案契约。**新增拟议 `AnalysisTaskSpec / AnswerSpec`，记录所问对象、分析粒度、过滤条件、时间范围、公式、分母、并列规则、输出列/键、单位与公开指定的舍入方式。将问题原文与公开补充要求同时解析；冲突显式标记。
2. **可验证语义上下文。**复用 `catalog/` 与已有画像能力，增加字段别名、枚举样本、日期编码、主外键和关联基数证据。对仅检索到部分数据、空结果或多对多膨胀给出可执行检查。
3. **SQL 语义检查。**执行前检查粒度、条件位置、分子分母、排序方向、并列与输出投影；执行后核对行数、唯一实体数、空值和范围。高风险候选最多增加一条有明确目的的交叉校验查询，不能让模型无上限枚举 SQL。
4. **类型化工具协议。**在已验证的 Magpie 函数调用路径上，增加参数 schema、受控字段候选、能力描述和错误分类；把 JSON 解析重试改为清晰的工具动作。SQL/字段名在数据库作用域内验证，不放宽 SqlGuard。记录经过裁剪的动作结构、schema 错误路径和修复类型，解决目前 invalid_action 过于笼统的问题；不保存凭据或无关原始资料。
5. **答案由证据组装。**每个字段绑定计算产物和方法；按公开要求统一类型、精度、集合与空结果语义。原始计算保留全精度，展示和提交只按题目明确规则舍入，禁止凭样本估计缺失的全量结果。对较大 ID 集合提供有总量核对的分块读取或受控集合聚合，不能把 LIMIT 200 或截断片段当作完整答案。

拟落点：`contracts/analysis.py`、`orchestration/analysis_plan.py`（新增），`catalog/`、`tools/sql_guard.py`、Stage 6 工具分发和评估器。现有受认证指标查询路径保持独立，先在新的研究配置中资格验证。

验收：并列冠军、生日/年龄方向、实体去重、分母、空集和日期边界的合成反例；69 道失败中的相关样本小批诊断；全 130 题与 61 道当前正确题逐题对照。对争议标签保持原评分，另外提交裁定材料。

### 第八期：让统计与建模真正由工具完成

1. **先修能力发现，再增工具。**现有 `fixed_analysis` 已有样本标准差、全量 Pearson 和单变量描述拟合；优先解决不会调用、参数错误或误判不支持的问题。描述拟合不冒充留出集预测评估。
2. **统计方法契约。**支持分组中位数/范围、IQR 与 Z-score 异常值、Pearson 系数及 p 值、偏度/峰度、适合数据规模的分布检验；明确 ddof、缺失处理、常量列、样本量、双尾条件与阈值。
3. **受控派生特征。**通过白名单表达式执行和、差、积、比值、日期提取及分组聚合，将结果写入新的派生快照。支持“构造特征→过滤→配对有效样本→计算统计”的完整链路，不要求模型手工展开复杂 SQL。
4. **真实多变量实验。**先实现确定性的线性回归和少量必要基线，再扩展其他模型；锁定特征、目标、随机种子、切分比例、分组/时间隔离、评估指标。预处理仅在训练折拟合，测试集不能参与特征选择或调参。
5. **复用沙箱与可复现报告。**扩展 Stage 3 版本化固定模板和 OCI 镜像；无目标 EDA 使用单独的分析快照契约，不伪造 target 迁就当前实验契约。Notebook 由执行记录生成，并实际重跑后才标为可复现。暂不引入宿主机任意 Python 执行。

拟落点：`data_science/` 的模板 v2、统计与特征算子、`contracts/data_science.py` 的兼容扩展、研究 Agent 的工具适配。参考 [scikit-learn 的数据泄漏说明](https://scikit-learn.org/stable/common_pitfalls.html) 和 [SciPy Pearson 定义](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.pearsonr.html)，正式实现时固定依赖版本及参数语义。

验收：手算小样本与独立库对照、全量和抽样区别、ddof 差异、训练/测试索引与泄漏检查；恢复案例 69、255 等确定问题。若方法约定不完整，公开默认与敏感性，不通过匹配参考标签倒推隐含种子。新增执行/导入协议时，先让基线与候选共同跑新协议，不把旧分数直接拼入对照。

### 第九期：把业务文档转成可验证的规则计算

1. **文档与表格联合上下文。**按问题先确定所需规则段落、版本、商户、交易、月份、MCC、ACI、费率表等；检索结果携带来源和字段映射，完整规则仍保存在可检查的结构化产物中。
2. **规则模型与确定性匹配。**表示列表成员、null 通配、区间、币种、自然月与多个适用规则；边界或歧义由原始文档和独立样例裁定。不得自行把空列表当通配或随意选择首条规则。
3. **专门的费用执行器。**根据公开手册计算 `fixed_amount + rate × transaction_value / 10000`，用十进制定点处理金额；月交易量与月欺诈量按规则定义聚合，区分金额占比和笔数占比。支持指定费率变动的反事实差额计算。
4. **任务图与有限修复。**将“计算月度特征→筛适用费用→逐笔计算→汇总→解释”分解成有输入/输出契约的节点。只重跑受影响节点，检查点引用原始数据哈希，限制总轮次和总预算。
5. **业务验证器。**以独立的小规模规则样例核对匹配、金额和差额；检查 null 通配、月份跨界、多个匹配及无匹配。最终每个答案均有规则依据、匹配记录与计算证据；缺失时明确失败。

拟落点：新的 `business/rules/`、费用/反事实工具、`orchestration/` 任务图和 `artifacts/` 证据适配。领域执行器应从通用规则契约扩展，不把 DABstep 题号或参考答案写成 if 分支。

验收：DABstep 1305/1273 的费用、1753/1464 的规则选择、1871 的变化量、70 的欺诈口径；新增按参数生成、独立计算和人工复核的业务题集。10 道公开 dev 题只能作为诊断小样本，不足以证明泛化。

### 第十期：把成功方法固化成可维护的能力

1. **可执行 Skill 注册。**每个 Skill 必须有版本、适用条件、输入输出、工具白名单、权限、预算、验证条件、失败处理、依赖和合成正反例；通过已有 admission 后才可调用。文档路由与执行能力分别登记。
2. **一般化经验复用。**保存错误类型、适用条件、有效修复和反例，不保存“题号→答案”。评估标签、参考 SQL 和本次复盘台账与生产检索空间隔离；自动提炼的经验先进入审核候选区。
3. **按任务路由与预算分配。**简单 SQL 使用短路径；统计题使用计算模板；复杂业务启用计划/执行/验证。重试按解析、计算、资料缺失等原因分配，不对缺能力或歧义任务机械重试。
4. **完整产品链路。**将已资格验证的开放分析能力接入现有 Supervisor，检查授权、数据域、结果证据、审计和交付；复用 Stage 5 已有反馈与版本治理，避免另建不受控闭环。
5. **未见题和重复验收。**冻结尚未用于开发的资产/任务与独立业务题集；至少三次完整配对重复。给出逐题增益/回退、置信区间、准确率—token—延迟关系及可取得的真实费用，再进行独立复核和真实环境影子验证。

## 五、执行顺序与评估纪律

1. **先做第七期三个最小增量：**a) 问题/答案契约与工具参数预检；b) 并列、分母、粒度、精度验证器；c) 同协议真实对照与标签争议侧账。每个增量单独提交，并保留失败证据。
2. 第八期先补派生特征、ddof 和真实回归评估，避免一开始追求完整 AutoML。第九期在规则与统计基础上推进。第十期的记忆和自适应机制须以稳定可验证的工具为前提。
3. 主对照固定源数据、队列、模型路径、服务参数、评分器、动作计数和预算；新增模型另设实验臂。新增工具属于系统能力变化，应记录其源码/方法指纹。导入、评分、步骤上限或执行语义改变时升级协议，并重新运行对照。
4. 首先采用原有六步/24,000 已观测 token/3,000 请求输出上限进行公平主对照；更长预算单列运行，不用多花预算后的成功率冒充同预算算法增益。多个角色与重试的消耗合并核算。
